CustomDomain™ doesn't yet cut numbered releases. The hosted service is
continuously updated, and the API is versioned separately (below).

## API versioning policy

The public API is versioned by URI major (`/v1`) and is **additive-only within a
version**: new optional fields and endpoints can appear, but existing fields
never change meaning or disappear without a new major version. See the
[API reference](/docs/api-reference) for the current surface.

  `list-provider-accounts` lists the provider accounts your workspace has connected, never a key, with `provider`,
  `domain` and `applicationId` to narrow it; `find-saved-access` lists the saved keys that may write one connected
  domain's records (`GET /v1/connections/{id}/saved-access`); and `use-saved-access` writes them with one

  `saved_access_not_usable` for a key that cannot act for the domain and `saved_access_write_failed` when the provider
  refused the write. A delegated agent token now reaches the three routes: `domains:read` for the two reads and
  `domains:connect` for the use, only for the keys that serve the application its grant is bound to, never a key a
  customer made at their own sign-in, and read as a viewer reads them (no account number, customer id or sign-in
  session id). What it does is in the audit log under the agent's grant. The saved access read now needs
  `domains:read` for an agent token, where it needed `domains:connect` and always answered an empty list. See
  [the MCP tools](/docs/mcp/overview) and [Provider accounts](/docs/connect-flow/provider-accounts).
