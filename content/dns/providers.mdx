title: DNS providers
description: Which DNS providers connect in one click, which take an API key, and which take a few records by hand.
---

When a customer enters a domain, we look up its nameservers to see who hosts its
DNS, then offer the easiest way in that works at that provider, in this order:

1. **Sign in with the provider** (OAuth) or **approve access at the provider**:
   one click, nothing to paste, and the one-time token is never stored.
2. **One-click setup** (Domain Connect): the provider applies our signed
   template after the customer approves it on the provider's site.
3. **An access role** (Amazon Route 53): the customer lets our AWS account
   change the zone, with no secret to paste.
4. **An API key**: the customer creates a scoped credential at the provider and
   pastes it; we write the records for them.
5. **Add the records by hand**: the exact rows to copy, with provider-specific
   steps and a link to the provider's DNS page. This works at every provider.

The console and the widget read the same verdict from
`POST /v1/domains:check` (its `rails` block and `recommended_rail`), so they
never disagree about what to show. `GET /v1/providers` lists every adapter and
`GET /v1/providers/census` routes every known provider to its mode.

Root domains (`acme.com` rather than `www.acme.com`) depend on what the provider
can hold at the zone apex; see [Root domains](/docs/dns/root-domains). For
records only you know (SES DKIM, a verification `TXT`), see
[Bring your own records](/docs/dns/bring-your-own-records).

## One click, nothing to paste

| Provider | How it connects | Notes |
| --- | --- | --- |
| Cloudflare | **Sign in with Cloudflare** | A root CNAME is fine: Cloudflare flattens it. |
| DNSimple, Netlify, Vercel, WordPress.com | **Sign in with the provider** | Netlify writes need the domain on Netlify DNS. |
| DigitalOcean, Linode (Akamai Cloud) | **Sign in with the provider** | Available when this deployment has registered an OAuth app for the provider; otherwise use a personal access token. |
| Porkbun | **Approve access at Porkbun** | Shown when enabled for this deployment. Porkbun only lets the API change domains that have API Access turned on. |
| OVHcloud | **Grant access at OVHcloud** | Shown when enabled for this deployment; otherwise use an OVHcloud application key. |
| NameSilo, Glauca Digital, Domain Chief | **One-click setup** (Domain Connect) | These providers serve our templates. |
| Amazon Route 53 | **Access role** (recommended) | Create a role in your AWS account that lets us change this zone; nothing secret to paste. An IAM access key works too. |

Sign-in and approval tokens are used once to write the records and are never
stored, which also means we cannot repair those records later without asking
again.

### Speaks one-click setup, but has not onboarded our templates

GoDaddy, IONOS, Aruba and Squarespace answer Domain Connect discovery but have
not onboarded our templates, so the console does not offer a one-click button
that would end on the provider's error page. Cloudflare answers too; its sign-in
is the one-click path. Until each provider onboards the templates, GoDaddy and
IONOS connect with an API key, and Aruba and Squarespace take the records by
hand.

### Using a provider token through the API

The BYO-token rail writes a connection's records with the customer's own
credential:

```bash
curl -X POST http://localhost:8080/v1/connections/<ID>/apply \
  -H "Authorization: Bearer <WIDGET_JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "cloudflare",
    "credential": { "token": "<scoped-provider-token>" }
  }'
```

`credential.token` carries every part of the credential in one string. The
console builds it from the separate fields; through the API you send it
yourself:

| `provider` | `credential.token` |
| --- | --- |
| `godaddy` | the Personal Access Token (a classic `key:secret` pair still works) |
| `namecheap` | `apiUser:apiKey`, optionally `:userName` and `:clientIp` |
| `route53` | `accessKeyId:secretAccessKey`, plus `:sessionToken` for temporary keys |
| `alidns` | `accessKeyId:accessKeySecret`, plus `:securityToken` for STS credentials |
| `allinkl` | `login:password`, plus `:otp` with two-factor login |
| `arsys` | `hostingDomain:apiPassword` |
| `azuredns` | `subscriptionId:resourceGroup:accessToken` |
| `cloudns` | `authId:password`, `sub:subAuthId:password` or `subuser:subAuthUser:password` |
| `constellix`, `dnsmadeeasy`, `spaceship` | `apiKey:secret` |
| `cpanel` | `user:token:host` |
| `easydns` | `token:key` |
| `gcpdns` | `projectId:accessToken` |
| `glesys` | `projectId:apiKey` |
| `ionos`, `uniteddomains` | `publicPrefix.secret` (one key, prefix and secret joined by a dot) |
| `luadns` | `email:apiKey` |
| `namebright` | `account:appName:secret` |
| `namecom` | `username:token` |
| `ovh` | `appKey:appSecret:consumerKey`, prefixed with `ca:` or `us:` outside Europe |
| `porkbun` | `apiKey:secretApiKey` |
| `simply` | `accountNumber:apiKey` |
| every other provider | the single token or key |

## Where keys are kept

Sign-in tokens and one-click setup store nothing. An API key is used for the
write and kept only when the customer leaves **Remember this key** ticked in the
console (through the API, only when the request sets `remember`). A kept key is
encrypted with AES-256-GCM, scoped to one workspace and provider, used only
server-side, and revocable any time under **Settings, Connected provider
accounts**. Account passwords and short-lived tokens (ALL-INKL.COM, Arsys,
Google Cloud DNS, Azure DNS, Openprovider) are never kept. See
[Remembering a key](/docs/dns/provider-setup#remembering-a-key-optional).

## One-click setup (Rail A)

One-click setup uses the provider-hosted Domain Connect protocol and is
redirect-based: the customer is sent to their provider, which applies a signed
template and returns. There is no server-to-server token. Discovery is via
`TXT _domainconnect.<domain>` and the provider's settings endpoint. Both the
synchronous redirect and the asynchronous variant are supported
(`POST /v1/connections/{id}/domainconnect:start`). The button is only offered
for providers that serve our templates.
