> **Live on customdomain.ai.** An agent can register, ask for scopes, and be
> approved by a human owner today. The **Agents** page in the console, where you
> review and revoke grants, is off by default for each workspace; see
> [In the console](#in-the-console).

An AI agent can act on your domains (search, connect and manage them) through the
[MCP server](/docs/mcp/overview). Before it can, a **real human owner approves
it**: the agent is a delegated, revocable connected client inside your
workspace, never a standalone login.

This is **human first**: the agent registers itself and asks for access, but a
person signs in to your console and approves exactly which scopes it gets, and
for how long. You can revoke it at any time.

## How it works

The agent runs a standard OAuth 2.0 authorization code flow with PKCE against the
control plane, then uses the resulting token at the MCP:

1. **Register**: the agent identifies itself with a Client ID Metadata Document,
   or self registers (Dynamic Client Registration) and gets a `client_id`.
2. **Authorize**: the agent sends the human to `GET /oauth/agent/authorize`; the
   control plane redirects the browser to your console's consent page.
3. **Consent**: the owner signs in, reviews the requested scopes, and approves.
4. **Token**: the agent exchanges the authorization code (plus its PKCE verifier)
   for a short lived **ES256 access token** and a refresh token.
5. **Act**: the agent calls MCP tools with the token. The MCP verifies the token
   **locally** against the published JWKS, checks it was issued for this server,
   and enforces the tool's required scope.

See [The OAuth flow](/docs/agents/oauth-flow) for the exact endpoints, and
[Managing access](/docs/agents/managing-access) for the owner side.

## In the console

- **Consent page** (`/agent/consent`). An agent that wants access sends you here,
  whether or not the Agents page is on. Nothing is granted until you approve.
- **Agents page** (`/app/settings/agents`). Review what each agent may do and
  revoke it. It is off by default for each workspace and switches on by itself when
  you approve an agent. You can also switch it on or off under
  **Settings → Features** (admins and owners). The agent step of the welcome (tick
  **Also let an AI agent connect and manage domains for me**) shows how to add
  CustomDomain™ to your agent and says **connected** once a grant exists.
- **Grants.** Each grant shows the agent, the application it acts in, when it was
  last used, and its scopes. **Revoke** ends it.

## Scopes

A grant carries one or more scopes; each MCP tool requires exactly one:

| Scope | Grants |
| --- | --- |
| `domains:read` | Observe only: availability, suggestions, connection, certificate and order status, diagnosis, provider discovery, listings, billing standing. |
| `domains:connect` | Set a domain up: connect, re-apply, recheck, forward, and email setup. It does not remove a domain. |
| `domains:disconnect` | Take a connected domain offline. Its own scope, so a grant that may set domains up cannot also remove them. |
| `domains:purchase` | **Spends money**: registers a domain. Isolated on its own scope, and requires a saved card and a monthly spend cap. Purchases through MCP are off on the hosted service. |

A read only token can never connect, disconnect or buy; a connect token can never
disconnect or buy. The owner approves a subset of what the agent requested, never
more.

**A grant approved before `domains:disconnect` existed does not carry it.** Its
agent can no longer disconnect a domain until the person approves the agent again
with that scope. Nothing else about the grant changes.

## What makes it safe

- **Human first**: a real owner consents; an agent can never approve itself. The
  consent call is authenticated by your server side workspace credential, never a
  browser token.
- **Least privilege**: access is scoped, and purchases are isolated on their own
  scope behind a spend cap and a required card on file.
- **Local validation**: access tokens are ES256, verified against the
  [JWKS](/docs/agents/oauth-flow#discovery) with no per request callback; they are
  short lived (15 minutes) and refreshed.
- **For this server only**: a token names the MCP endpoint as its audience, and the
  MCP refuses a token issued for anything else.
- **Revocable**: revoke a grant from the console at any time; the agent's tokens
  stop working within one token lifetime.
- **Owner emails**: you are emailed when an agent connects, when it acts, and
  immediately when it spends money.
- **A trail**: what an agent does and spends is in the audit log, under the actor
  `agent:<grant id>`.
