### Which DNS providers auto-configure records?

The hosted service writes the records for the customer at 47 DNS providers,
through a sign-in, an API key or an access role (Cloudflare, Route 53, Google
Cloud DNS, Azure DNS, GoDaddy, Namecheap, and more). `GET /v1/providers` lists
every built-in adapter; those with `automatic: true` can write, and one of
them, PowerDNS, points at a server you run yourself. NameSilo, Glauca
Digital and Domain Chief add provider-hosted one-click setup, a redirect with
no token at all. More than 150 providers, registrars and domain platforms are
known by name (`GET /v1/providers/census`). Any provider can be connected by
adding the records by hand, and 125 providers and platforms have their own
steps for that. See
[DNS providers](/docs/dns/providers) for which way each one connects and
[Provider setup](/docs/dns/provider-setup) for per-provider credential steps
and eligibility gates.

### Can I buy a new domain here too?

Yes, under **Sell → Buy a domain** in the console. Checkout only *authorizes* your
card; the domain is registered server-side, and the card is captured only after
registration succeeds (a failure releases the hold, so you pay nothing). The
purchased domain shows up in Domains already connected. See
[Buying a domain](/docs/sell/buying-a-domain).

### How does a domain actually get configured?

Through one of four [rails](/docs/connect-flow/overview#the-four-rails): the
customer authorizes their DNS provider via OAuth (records written with a one-time
token), a one-click setup redirect, a scoped API token you pass once, or the
guided-manual copy-paste flow. `POST /v1/domains:check` tells you which are
available for a given domain.

### Is my provider API key stored?

Only if you keep **Remember this key** ticked when you connect in the console
(through the API, only when the request sets `remember`). A kept key is
encrypted at rest, scoped to your workspace and that provider, and reused for
your other domains in one click; the plaintext never leaves the server, and you
can revoke it any time under **Settings, Connected provider accounts**. Untick
the box and the key is used once to write the records, then forgotten. Account
passwords and tokens that expire within hours are never kept. See
[Provider setup](/docs/dns/provider-setup#remembering-a-key-optional).

### Can I connect several domains on the same provider account at once?

Yes, for **Cloudflare, GoDaddy, Route 53, and Namecheap**. After you apply a key
to one domain, the console offers to list the account's other domains and connect
them (all or a subset) in one step. See
[Bulk connect](/docs/connect-flow/verify-and-go-live#bulk-connect-more-domains-on-one-account).

### Does it support apex domains as well as subdomains?

Yes. A connection's `host` is empty for the apex or the subdomain label
otherwise. A root domain works at **every** provider: where the provider has a
root-CNAME type (ALIAS/ANAME/flattened CNAME: Cloudflare, Route 53, DNSimple,
DigitalOcean…) the record set uses it; everywhere else (GoDaddy, Namecheap,
Name.com, OVH…) it uses `A` records pointing at our edge. `POST
/v1/domains:check` returns `apex_supported` (the provider fact) and
`apex_message` (set only when *this* record set can't be realized) so you can
steer the customer. See [Root domains](/docs/dns/root-domains).

### Does it support wildcard domains?

`POST /v1/domains:check` returns a `wildcard_support` flag per detected provider.
Whether you offer wildcard in your product depends on how you use that flag in
your onboarding flow.

### How long does DNS propagation usually take?

For records written for the customer (a sign-in, one-click setup or an API
key), usually seconds: the connection is checked every five seconds at first,
and when public resolvers still hold an old or missing answer, we ask the
zone's own nameservers. Records added by hand are verified as soon as the
provider serves them, so the wait is mostly how long the customer takes. Some
visitors can still reach the old host until a replaced record's TTL runs out.
The connection sits in `propagating` (or `pending`, for records added by hand)
until every desired record resolves; `GET /v1/connections/{id}` shows current
status.

### What happens if I revoke or delete an API key?

Revocation is immediate: a revoked key stops authenticating on its next request.
Keys are never returned by list endpoints after creation; only metadata (`last4`,
`created_at`, `revoked_at`) is visible.

### Can a connection lose its "live" status?

The lifecycle is forward-only, so a `live` connection isn't demoted
automatically. But [Monitor](/docs/webhooks/overview#event-catalog) detects when a
live domain's records stop resolving and fires `domain.record_missing`, so you can
react. See [Offboarding](/docs/connect-flow/offboarding).

### Is there a sandbox / test mode?

Yes. API keys and applications carry an environment (`production` / `staging` /
`development`), and keys are prefixed `cd_test_` / `cd_live_` (keys created
before that prefix change use `sk_test_` / `sk_live_` and keep working). `make up` runs the
full stack locally (see the [Quickstart](/docs/getting-started/quickstart)).
