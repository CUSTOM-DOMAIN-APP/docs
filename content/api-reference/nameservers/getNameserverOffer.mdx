      - content: >-
          What `POST /connections/{id}/nameservers:migrate` would accept for this
          domain right now, for the caller who asks: whether a move can start
          (`available`, and `reason` when it cannot), where it would host the zone
          (`target`, the application's setting, else `managed`), who the domain is
          registered with, and the three ways the nameservers can change (`paths`):
          `api` with one of the connected accounts at the registrar listed in
          `accounts`, `agent` through the cloud browser the person signs in to, and
          `manual` by the person at the registrar. The console's "Host its DNS
          instead" sheet reads it, so it offers nothing the move would refuse. It
          reads and changes nothing. The accounts are the ones this caller may use, at
          the registrar RDAP names, whose scope already holds the zone, whose API
          changes nameservers, and never an end user's own key; a registrar we do not
          route to has none. The reasons are the move's own: `ns_not_offered` (an
          agent token while the application's DNS hosting is off, decision D9: an API
          key and the console are not held to it), `dns_host_unavailable` (the
          application's DNS host account no longer works), `move_open` (a move for
          this zone is already under way), `registrar_locks_nameservers`, the reasons
          of managed DNS (`disabled`, `platform_subdomain`, `unsupported_tld`,
          `reserved`), `zone_limit` (a cap of the engine's own: the workspace's or the
          deployment's) and `plan_zone_limit` (the workspace holds as many hosted
          zones as its plan counts, decision D8). The plan's count is the offer's
          limit and the move's start does not refuse at it; the caps are refused there
          too (`managed_dns_limit`). A domain whose zone already exists adds none, so
          neither limit applies to it. An API key, an app scoped token and a delegated
          agent token with `domains:read` may ask. An end user's widget token may not
          (`403`): its application offers it the move in the domain check, and it
          starts it with its consent.
