    contents:
      - content: >-
          Moves the domain back, to one of two places (`rollback_target`): the
          nameservers it had before (`previous`), or the registrar's own DNS
          (`registrar_default`). Without a choice: the old nameservers while
          they still answer for the zone, else the registrar's own DNS. The old
          nameservers are asked first, because a DNS host may have deleted the
          zone since (Cloudflare deletes a moved zone after 7 days); moving back
          to ones that no longer answer is refused (`409 old_dns_gone`). A move
          back to a domain that used the registrar's own DNS at the start goes
          through the registrar's reset call, not its names set as custom ones.
          With a key (sent once, or the migration's connected account) the
          registrar's API makes it (`rollback_path: api`); otherwise the cloud
          browser (`agent`) or a person (`manual`, `next_step` says what to set
          or choose). A migration that changed nothing at the registrar yet is
          simply stopped (`none`). Any cloud browser session still working on
          the move is ended first. Idempotent. A widget token may move back, and
          choose where, but may not send a key. A delegated agent token needs
          `domains:connect`, and a move back it makes is recorded in the audit
          log as `agent.acted` ("moved a domain's nameservers back") for its
          grant.
