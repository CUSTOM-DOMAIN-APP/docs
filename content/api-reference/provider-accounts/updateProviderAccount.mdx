      - content: >-
          Narrowing the scope detaches the domains it no longer covers; they
          stay connected, without continuous access. Switching to `one_time`
          deletes the key now. Switching to `continuous` needs the key still
          held. Changing `access`, `scope` or `domains` takes an admin, an owner
          or the member who connected the account (`403` otherwise); the label
          is anyone's who operates applications. A key an end user's secure
          sign-in made in the widget is never widened: a change that adds a
          domain or sets `scope` to `all` answers `403`, whoever asks; renaming,
          narrowing and revoking still work. `continuous` access for a
          credential that is used once and never kept answers `422`
          `use_once_credential`. A change is recorded in the audit log
          (`provider_account.updated`, with the label, access, scope, domains
          and applications before and after).
      - content: >-
          `application_ids` is the whole set of other applications of the
          workspace that may use a key bound to one application, besides its own
          (`application_id`, which always serves). Sending it replaces the set:
          name an application to share the key with it, leave it out to take it
          back, send `[]` to share with none. Naming the key's own application,
          a repeat or a blank changes nothing. It takes an admin or an owner,
          never only the member who connected the key (`403` otherwise), and
          answers `403` for a key an end user's sign-in made, which is never
          shared, and `404` for an application that is not the workspace's. A
          key bound to no application already serves every application, so
          naming one answers `422` `serves_every_application`; at most 100 are
          taken in a call (`400` beyond). Each application shared is recorded in
          the audit log as `provider_account.shared`, and each taken out as
          `provider_account.unshared`, both naming the applications served
          before and after and the ones changed (`application_ids`). Taking an
          application out detaches the domains of it that were using the key:
          they stay connected, without continuous access, and each domain's
          timeline records `access_revoked` with the reason `unshared`.
