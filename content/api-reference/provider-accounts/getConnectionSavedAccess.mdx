          The saved access resolver's answer for the connection's domain: the workspace's kept provider keys that may write its records for the caller, best first, with no sign in and no new key. The same answer is `rails.saved_access` on `POST /domains:check`. A key whose scope holds the domain's zone is `ready`; a key made at a secure sign in started in the console may be listed with `ready: false` after one read with it showed it reaches the zone. An end user's widget token gets an empty list.
