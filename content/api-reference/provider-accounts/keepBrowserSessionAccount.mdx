      - content: >-
          **The console only**, for the member who started the account sign in (`POST
          /provider-accounts:sign-in`). The key that waits (`key_ready`) is kept as a
          provider account only now, in one step, for the domains the person
          confirmed: `scope` is always named (`all` of the account's domains, or
          `selected` ones), and each selected domain must be one the key lists (`422`
          `domain_not_listed`). A call that is refused keeps nothing and leaves the
          session waiting inside its ten minutes. The key is claimed for the call, so
          a double press stores it once (`409` `browser_wrong_state` for the second).


          The account is the workspace's own, made by secure sign in in the console
          (`origin: browser_agent`, `made_by.how: console_sign_in`), for the
          application the sign in named, or for every application when it named none.
          `access` is `continuous` (the default) or `one_time`; a provider whose
          credential is used once and never kept (see `POST /provider-accounts`) is
          `one_time` only (`422` `use_once_credential`). `application_ids` shares the
          key with other applications of the workspace (decision D5): an admin or an
          owner only (`403`), every id one of the workspace's (`404` otherwise), and a
          key for every application takes none (`422` `serves_every_application`).


          When the workspace already holds a continuous key for the same provider
          account, for the same application, the new key is swapped into that account
          instead of adding a row: the answer is `200` with `swapped: true`, the
          replaced key is named for deletion by hand on the account
          (`agent_key.old_key`), the domains chosen join its scope and never narrow
          it, and widening it takes an admin, an owner or the member who connected it
          (`403` otherwise). GoDaddy is the exception until its written permission is
          on file: its second sign in adds a second row. Every account made, swapped
          or shared is in the audit log (`provider_account.created`, `.key_replaced`,
          `.updated`, `.shared`).


          A session of another workspace or member, a connect session and an unknown
          id are `404`; a session that is not waiting for the keep step is `409`, and
          one whose ten minutes passed `410`.
