      - content: >-
          Writes the connection's records with one of the kept keys `GET
          /connections/{id}/saved-access` answers for it (`account_id`), and
          links the key to the domain, so later repairs and the removal use it.
          A key offered with `ready: false` takes the domain's zone into its
          scope once the write worked (`provider_account.domain_added` in the
          audit log). An account the resolver does not answer for this domain
          and caller is `409` `saved_access_not_usable`, and so is a key at
          another provider than the one a live or propagating domain's DNS is
          at, or a key whose scope does not hold such a domain yet (such a
          domain is linked without a write, and a scope widens only after a
          write). A test mode domain is refused (`403` `sandbox_not_allowed`). A
          write that fails links nothing and leaves the key's scope as it was,
          and records the failure on the domain (its `error_code` and
          `error_message`): `502` `saved_access_write_failed`, with the
          provider's words. Records written but a key that could not be linked
          is `500` `saved_access_link_failed`: try again. A domain kept by an
          end user's own sign in key is left as it is (`409`).
