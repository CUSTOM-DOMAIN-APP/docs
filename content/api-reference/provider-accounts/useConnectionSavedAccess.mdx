      - content: >-
          Writes the connection's records with one of the kept keys `GET
          /connections/{id}/saved-access` answers for it (`account_id`), and
          links the key to the domain, so later repairs and the removal use it.
          A key offered with `ready: false` takes the domain's zone into its
          scope once the write worked (`provider_account.domain_added` in the
          audit log). An account the resolver does not answer for this domain
          and caller is `409` `saved_access_not_usable`, and so is a key at
          another provider than the one a live or propagating domain's DNS is
          at, or a key whose scope does not hold such a domain yet (such a
          domain is linked without a write, and a scope widens only after a
          write). A test mode domain is refused (`403` `sandbox_not_allowed`). A
          write that fails links nothing and leaves the key's scope as it was,
          and records the failure on the domain (its `error_code` and
          `error_message`): `502` `saved_access_write_failed`, with the
          provider's words. A provider that writes one record set at a time can
          fail after the first, so the zone may hold some of the records even
          though the call failed. Records written but a key that could not be
          linked is `500` `saved_access_link_failed`: try again. A domain kept
          by an end user's own sign in key is left as it is (`409`).

          A delegated agent token uses a saved key with `domains:connect` (the
          MCP's `use-saved-access`), for a connection of the application its
          grant is bound to and a key the resolver answers for that application.
          The response's `account` is then the viewer's view of it (no
          `account_ref`, `end_user_ref`, `agent_key.account` or
          `agent_key.session_id`, no `agent_key.name`, no `made_by.by` and no
          `created_by`, an empty `application_ids`, with the same limit on its
          `domains` as the list, and read as the list reads a key shared from
          another application), and the audit log records `agent.acted` for the
          grant once whenever the records were written, the key linked or the
          write failed at the provider, whatever the answer (its detail says
          when the provider answered with an error); a use refused before
          anything was sent, such as one with no records to write, leaves no
          row. A token without `domains:connect` is `403`. An end user's widget
          token is held to the same end user policy as `browser:start` (`403`
          `token_not_bound` for a token bound to no domain, `403`
          `token_wrong_end_user` for one minted for another end user than the
          connection's, or for none), and then reaches the route but may not use
          a key yet, though `GET /connections/{id}/saved-access` offers it its
          own: `409` `saved_access_not_usable` for an account that exists.
