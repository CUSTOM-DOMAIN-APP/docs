    contents:
      - content: >-
          Creates a connection for each domain under the application and writes
          its records with the account's key (keeping the CAA and TXT values
          already there and recording what each write replaced). Each domain is
          linked to the account once its records are written; a domain whose
          write fails is not linked and keeps the access it had. A continuous
          account then keeps the linked domains in sync. A domain the
          application already serves is only linked (`provider_account.relinked`
          in the audit log), and only to a key at the provider its DNS is at
          whose scope already holds it; any other such domain is answered
          `already` with the reason and left as it is. A one time account
          deletes its key once the domains are connected, even when the caller
          has gone away by then, and past its hour answers `409`. A domain in a
          zone the key does not reach fails alone (`zone_not_reached` on the
          connection); the account is flagged `needs_reconnect` only when the
          provider refuses the key itself, which is checked with a request that
          does not depend on the zone. A key made at a secure sign in serves its
          own application and the applications an admin shared it with
          (`application_ids`); naming any other application's id answers `403`
          (this key is not shared with this application; an admin or an owner
          can share it). A domain outside the key's scope answers `400`, except
          for a key a member of the workspace made at a sign in started in the
          console (the console's signed call, not an API key that names the
          console): when a read of the domain's zone with the key works, the
          domain is connected with no new sign in, and the zone is added to the
          key's scope once a write there works (`provider_account.domain_added`
          in the audit log). A key an end user's secure sign-in made in the
          widget, or one a sign in started through the API made, answers `403`:
          it connects domains only through that end user's own widget session. A
          domain the application already has, kept by such a key, is left as it
          is (`already`, not re-linked). Takes an admin, an owner or the member
          who connected the account.
