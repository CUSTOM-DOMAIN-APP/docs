      - content: >-
          The workspace's provider accounts with their access mode, the domains
          they cover, when they were last used and when they expire, and whether
          the caller may manage each one (`can_manage`); and, in `kept_access`,
          the sign-ins and Domain Connect authorizations kept per domain,
          grouped by provider. A kept sign-in is stopped per domain with `DELETE
          /connections/{id}/grant`. A viewer reads them without
          `agent_key.account` (an end user's customer number at the provider)
          and `agent_key.session_id`.


          `?provider=` keeps one provider's accounts. `?domain=` keeps the ones
          that may act for that domain for the caller, best first, by the saved
          access resolver's rules (see `GET /connections/{id}/saved-access`), for
          `?application_id=` or the API key's own application (`404` for an
          application of another workspace), and adds them as `saved_access`.


          A delegated agent token lists with `domains:read` (the MCP's `list-provider-accounts`), and sees less than an API key: only the workspace's keys that serve the application its grant is bound to, never a key an end user's own sign in made, each as a viewer reads it (no `account_ref`, `end_user_ref`, `agent_key.account` or `agent_key.session_id`) with only that application's connections and only the `domains` that no other application of the workspace has connected (a zone in which another application holds a domain is left out, unless the grant's own application holds one in it too), `can_manage` false, and an empty `kept_access`. `?application_id=` may only repeat the grant's own application (`403` otherwise). A token without `domains:read` is `403`.
