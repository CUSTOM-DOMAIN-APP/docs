      - content: >-
          **The console only.** Starts "Sign in with &lt;company&gt;", the way to add a
          provider account with no domain by the company's own OAuth consent screen. It
          answers the address to open in a popup. When the person approves access there,
          the shared sign-in callback (`GET /connect/oauth/callback`) makes the account:
          every domain the sign-in reaches, continuous access, with the access token and
          the refresh token kept encrypted (a token near its end is refreshed before it is
          used). The popup posts `{ok, purpose: "account", provider, account_id}` to
          `return_origin`, or `{ok: false, code, message}` when the person declined or it
          failed. A token the account did not keep is revoked at the company. Signing in
          again to the same account (DNSimple's account, a Vercel team) renews the account
          it made before instead of adding a second one.
      - content: >-
          The state binds the workspace, the member who started it and the application, is
          single use and lives ten minutes. Nothing is written before the callback.
      - content: >-
          Offered only where `account_ways` of `GET /providers` names `oauth` for the
          company. Any other is `403` `oauth_account_unavailable`. The caller is the
          console's own call, as for `POST /provider-accounts:sign-in` (`403`
          `browser_account_unavailable` otherwise; a viewer is `403` `forbidden`). A
          workspace an operator suspended starts none (`403` `workspace_suspended`).
