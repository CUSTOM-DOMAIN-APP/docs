      - content: >-
          The session view. Every call is the popup's heartbeat: a session that is not
          polled for 90 seconds before approval is ended and its browser released. The
          response is `Cache-Control: no-store`, because the view can carry the live
          view address, which anyone holding can drive.


          Once the session has kept a lasting API key for the connection, the view
          carries `kept_key`: the key's `name`, the provider's `page` that deletes
          keys, its `rights` and when it ends (`expires_at`), so the last screen can
          say which key was kept and where to remove it. A key that was made and not
          kept is `left_key` instead.


          With an API key instead (the console's own call, on its signed visitor
          forward, for the member who started it), the route answers an account sign
          in's state instead of the popup's view (`AccountSignInSession`): no live
          view address, no token, no domain. While the key waits for the keep step
          (`key_ready`) it carries the `zones` the key lists, what the key is (`key`)
          and when the wait ends (`deadline`); after an end that left the key at the
          provider it carries `left_key`. A session of another workspace or another
          member, a connect session and an unknown id are all `404`, and a viewer is
          `403`. Any other credential, an API key without the console's forward
          included, is read as the popup's: a widget token, an agent token, the
          operator's key and such an API key fail the token check (`401`). Reading it
          is not a heartbeat.
