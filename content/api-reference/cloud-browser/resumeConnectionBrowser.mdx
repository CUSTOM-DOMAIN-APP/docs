          **Customer present only.** The customer left the popup to read a code
          in their mail app and the phone threw it away, or closed the window by
          mistake, while the session still waits on them. This hands the SAME
          session (the same remote browser, still on the provider's page) to a
          new popup: the answer is the one of `browser:start`, with a new single
          use bootstrap code in the popup's address, and the previous popup's
          session token stops working at once. One popup at a time.


          Allowed only while the session waits on the customer: about to sign
          in, signing in (a code prompt included), or while the agent has handed
          the page back. It takes the gate of `browser:start` (an end user's
          widget token bound to the domain and the end user, or the console, and
          an `Origin` on the return origin allowlist; `403 token_not_bound` and
          `403 token_wrong_end_user` as there), and only the caller that started
          the session may resume it: the same end user's widget token, or the
          console. Anyone else, an API key included, gets `browser_not_waiting`.
          A session takes a few, one every few seconds.
