      - content: >-
          Accepts the management key (the body `tenant_id` selects the tenant)
          or a tenant-scoped API key (the app is always created in the key's own
          tenant; any body `tenant_id` is ignored).


          Send `"sandbox": true` to make a **test mode** application: a place to
          run the widget, the API and webhooks end to end before you have a real
          customer domain. It connects only reserved `.test` names (the first
          label picks the outcome: `conflict.acme.test` stays pending with
          `domain_already_connected`, `timeout.acme.test` fails after about a
          minute with `propagation_timeout`, any other name goes live after
          about 15 seconds), uses the manual rail only, and counts for nothing:
          no free domain, no quota, no billing, no metering and no reporting.
          Webhook events from it carry `"sandbox": true`. A workspace can hold
          up to 3 test mode applications, each up to 100 connections
          (`sandbox_limit`). A test mode application is always a development
          application, so leave `environment` out. A live application never
          connects a `.test` name (`sandbox_domain_reserved`), and a test mode
          one never connects a real name (`sandbox_domain_required`).
