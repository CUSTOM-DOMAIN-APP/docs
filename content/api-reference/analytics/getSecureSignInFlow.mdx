          How secure sign-in sessions (the cloud browser) went in the window, overall and per DNS provider. `funnel` counts the sessions that reached each stage (started, sign-in shown, signed in, plan ready, making changes, done) with the drop from the stage before. `times` is the median and 90th percentile of the seconds from the stage before it that has a time, over the sessions that reached it; `total` is start to done for the sessions that finished. `stops` files every session that ended without finishing under one plain reason (`browser_not_started`, `left_at_sign_in`, `code_never_entered`, `provider_page_not_understood`, `provider_refused`, `timed_out`, `cancelled`, `changes_failed`, `error`). A session finished by hand counts in `done_by_hand`, a running one in `in_progress`; neither is in the funnel's done or the stops. Counts and times only: no domain, person or anything typed. Scoped to the key's workspace and `app_id` when given. At most 20000 sessions are read, newest first (`truncated`). API key; any member role.
