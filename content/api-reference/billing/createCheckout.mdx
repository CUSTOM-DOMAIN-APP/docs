    contents:
      - content: >-
          Starts a subscription Checkout for the caller's workspace. Requires
          `billing:manage` (owners and admins); a widget token is refused. The
          session allows promotion codes and collects the card up front. A new
          workspace's first subscription starts with a 14 day trial; a workspace
          inside its grace period (the retired Free plan) gets a trial that ends
          when its grace ends, so subscribing early never costs a day; anyone
          else is charged today. A workspace that already has a running
          subscription gets `409` (change the plan with `/billing/change-plan`
          instead). Nothing is granted until Stripe confirms the checkout.


          Supply EITHER `return_url` (embedded Checkout, the response carries
          `client_secret`) OR both `success_url` and `cancel_url` (hosted
          Checkout, the response carries `url`).


          `ui_mode` is optional and picks how the session is shown. Leave it out
          (a `null` or an empty string counts as leaving it out), or send
          `embedded`, for the behavior from before it existed: Stripe Embedded
          Checkout when `return_url` is set, and the hosted redirect when only
          `success_url` and `cancel_url` are. `elements` is Elements with the
          Checkout Sessions API: the caller renders the whole page (the plan,
          the price, the trial, the promotion code field, the totals) and mounts
          only Stripe's Payment Element with the returned `client_secret`, so
          the page can wear its own theme. It needs `return_url`, which is where
          redirect based payment methods and the finished payment land, and the
          session is created on a Stripe API version of the dahlia release train
          (the billing guide names the exact version), so mount it with a
          Stripe.js of that train. The trial, the promotion codes and the card
          up front are the same in every mode. The response's `ui_mode` says
          what was really created (`embedded`, `elements` or `hosted`): an
          `elements` request answers `embedded` when Stripe could not create an
          Elements session, so read it before mounting anything. `hosted` is
          only ever an answer, never a request value: a client that keeps the
          response's `ui_mode` must not send it back (the redirect flow is
          chosen by sending `success_url` and `cancel_url` without
          `return_url`). Any other value is a 400.
