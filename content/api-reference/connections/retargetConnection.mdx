    contents:
      - content: >-
          A connection keeps the routing it connected with, so changing an
          application's routing moves no existing domain. This moves one: the
          domain's expected records become those of the application's current
          routing. The customer's DNS is not changed, so the domain needs its
          records updated (returned in `records`) before it serves on the new
          routing. Moving a live domain off the edge stops edge serving at once
          (`stops_edge_serving`).


          A no-op (`moved: false`) when the domain already has the application's
          routing. Refused (409) when the domain's records are stored: records
          your backend supplied (change them with `PUT
          /connections/{id}/records`) or records written into the customer's DNS
          during setup (disconnect and reconnect to move it). Recorded in the
          audit log as `connection.retargeted`.
