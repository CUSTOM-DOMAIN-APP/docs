      - content: >-
          Returns the connection object and its records. The connection carries
          a `managed` boolean: `true` when it opted in to **managed mode** (the
          control plane holds a durable, encrypted async grant so it can
          re-apply / revert the template server-side without re-consent);
          `false` (omitted on the wire) for the default use-once connection.


          `dns_hosting` says who runs the domain's DNS, and `reach` how
          CustomDomain™ reaches it to write records (a kept account, a kept
          sign-in, one-click setup, DNS hosting, or nothing). `reach` is for the
          platform's own servers (an API key, an `app`-scoped token or an agent
          token); an end user's `connect`-scoped token reads `dns_hosting` only.


          A delegated agent token needs `domains:read` and reads only
          connections of its own application; another application's connection
          answers `404`.
